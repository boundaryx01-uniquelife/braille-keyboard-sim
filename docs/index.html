기록

점자 코드입력 키보드 — 전체 과정 설명

아이디어가 어떻게 기기가 되었는지, 무엇을 어떻게 확인했고 무엇을 아직 모르는지를 처음부터 끝까지 적은 글이다. 만드는 방법만 필요하면 만드는 설명서로 가면 된다.

기준일: 2026-09-24. 이 글의 모든 "확인했다"는 아래 두 가지 중 하나를 뜻하고, 표시를 붙였다.

  • PC 검증됨 — 하드웨어 없이 컴퓨터에서 자동 테스트로 확인했다.
  • 실물 미검증 — 실제 기판·스위치·화면·블루투스가 있어야 확인할 수 있어서 아직 확인하지 못했다.

1. 한 문장 요약

시각장애인이 점 6개 키로 점자를 직접 치면, 블루투스로 폰·PC에 글자가 입력되고, 옆에서 보는 교사·보호자는 작은 화면으로 무엇을 쳤는지 확인할 수 있는 저가 오픈소스 점자 키보드. 영어(Grade 1)와 한글을 지원한다. 목표는 기기 하나로 끝나지 않고 기기 + 공개(GitHub·MakerWorld) + 강의자료까지다.

지금 사용자는 LilyGO T-Display(ESP32와 화면이 붙은 보드, 판매 표기 TS0636G-T Display)를 갖고 있고, 스위치와 케이스는 아직 없다. 그래서 상태는 이렇다.

구성요소상태근거
동시 입력(chord) 판정, 백스페이스, 대문자, 언어 전환 PC 검증됨손으로 규칙에서 도출한 95개 테스트벡터를 파이썬·C++ 양쪽이 통과
한글 점자 → 한글 (약자·약어·숫자 포함) PC 검증됨2024 규정 공식 예시 대조, 독립 출처 대조, C++ 대량 대조
화면 배치 (T-Display, OLED) PC 검증됨실제 글꼴로 화면을 그려 배치 점검
ESP32 빌드 컴파일 성공두 보드 모두 (T-Display 445,895바이트)
실제 화면에 나오는 모습 실물 미검증방향·색·가장자리·갱신 시간
스위치 배선과 실제 입력 감각 실물 미검증스위치가 아직 없다
블루투스 키보드로 폰·PC에 입력 미구현Phase 3
한글을 호스트(폰·PC)로 보내는 방식 미검증시험해 본 적 없는 설계안뿐
케이스, 키캡 초안만실물 부품이 없어 문헌 치수로 그렸다
점자 사용자·전문가의 확인 받지 못함규정 문서로만 대조했다

2. 어떻게 여기까지 왔나

출발: 도구 만들기가 아니라 같이 생각하는 자리

처음 요청은 MakerWorld의 Makerlab(OpenSCAD 기반 Parametric Model Maker)용 작업 공간이었다. 대화하면서 방향이 바뀌었다. 주문받아 만들어 주는 공장이 아니라, 일상의 불편함에서 "이거 만들어 볼 만한데?"를 먼저 잡아내고, 발명적 사고로 다듬고, OpenSCAD로 되는지 확인하고, MakerWorld에서 이미 레드오션인지 살핀 뒤에 만드는 자리. 이 방식은 저장소 루트의 CLAUDE.md에 적혀 있다.

점자 키캡 → 진짜 점자 키보드

  1. "시각장애인용 점자 클리커" 아이디어에서 시작했다. 사용자가 말한 범위는 기계식 키보드 스위치를 이용한 피짓토이였다.
  2. 그래서 알파벳 한 글자에 대응하는 점자 키캡 생성기를 만들었다 (openscad/projects/braille_keycap_maker). MakerWorld에 이미 있는 한글 키캡 메이커와 비교했을 때 부족한 점을 사용자가 짚었다.
  3. 사용자는 두 갈래를 모두 하기로 했다. (1) 장난감(클리커), (2) 실제로 쓰는 점자 키보드. 2번은 자료 조사부터 하기로 했다.
  4. 조사에서 같은 구조의 선례(BrailleBridge, Apache-2.0)를 찾아 구조를 뜯어봤다. 여기서 가져온 교훈이 설계의 뼈대가 됐다.
    • 점자는 여러 키를 동시에 눌러서 한 글자를 만든다(chord 입력, Perkins 방식). 영어·한글 등 언어가 달라도 하드웨어는 같고 표(테이블)만 바꾸면 된다.
    • 블루투스 키보드 기능을 직접 구현했다가 두 번 망가진 사례가 있어서, 우리는 검증된 라이브러리를 쓰기로 했다.
    • 부트 스트래핑 핀(GPIO12 등)을 스위치에 쓰면 부팅이 꼬일 수 있어 피했다.
    • 라이선스가 Apache-2.0이라 코드를 복사하지 않고 구조만 참고해 새로 작성했다.
  5. 사용자의 질문이 기획을 넓혔다. "화면이 달린 ESP32도 많던데 화면을 쓰면 사용성이 좋아지지 않을까?" → 옆에서 지켜보는 교사·보호자가 입력을 확인할 수 있다. "점자를 화면이 아니라 소리로 알려 주는 건?" → 이어폰으로 글자를 읽어 주는 학습 모드(후반 단계로 미룸).
  6. 그리고 최종 목표를 정하고 순서대로 계획했다: 기기 + 공개 + 강의자료, 9단계 (firmware/PLAN.md).

실행: 부품 없이 할 수 있는 것부터

실물 부품이 없어서, 하드웨어 없이 PC에서 정답을 먼저 정의하고 검증하는 순서로 갔다.

단계한 일상태
1파이썬 기준 구현: 동시 입력 상태머신 + 영어 표 + 테스트벡터
2같은 규칙을 C++로 이식(헤더 전용), 가짜 Arduino API로 스케치를 PC에서 돌려 핀 신호부터 시리얼 출력까지 검증, 부품 주문서 작성 (주문은 사용자가 한다)
4OpenSCAD 케이스 초안 (스위치 8개 + ESP32 DevKit 보드) 초안, 실물 fit 미검증
6한글: 인코더·디코더, 약자·약어·숫자, 언어 전환, 낱말 단위 입력 계층 PC까지
5화면: 최근 입력·언어·상태를 실제 글꼴로 그리고 검증 PC까지
3실물 조립과 블루투스스위치가 오면

그 사이 사용자가 T-Display를 이미 갖고 있다고 알려 줬다. 계획은 화면 별도 모듈(SSD1306 OLED)이었는데, 화면 일체형 보드라서 두 보드를 다 지원하도록 바꿨다. 그리는 코드와 글꼴은 같고 화면 크기와 핀 배치만 다르다. T-Display는 화면이 GPIO 6개를 쓰고 보드 버튼·배터리 회로가 4개를 써서, 스위치 핀 배치를 따로 정했다.

3. 기기가 하는 일

스위치 8개 (점1~6, 스페이스, 시프트)
  |
  v
디바운스 (5ms) - 접점의 떨림을 한 번의 눌림으로 만든다
  |
  v
동시 입력 판정 (ChordMachine) - 180ms 창 안의 점을 합쳐 토큰 하나로
  |
  v
입력 계층 (Typist) - 영어는 바로, 한글은 낱말 단위로 모은다
  |
  +--> 호스트로 보낼 것 (HOST 줄) - 지금은 시리얼, 나중에 블루투스
  |
  +--> 화면에 그릴 것 - 상태줄과 최근 글자

동시 입력(chord) 규칙

  • 점 키를 처음 누른 순간부터 180ms 안에 눌린 점들을 하나로 합쳐 한 글자로 본다.
  • 창이 닫힌 뒤에도 계속 눌려 있는 점은 모든 점 키를 뗄 때까지 무시한다(같은 글자가 두 번 나오지 않게).
  • 스페이스는 점 키가 눌려 있지 않을 때 누르는 순간 공백.
  • 시프트를 누른 채 친 글자는 대문자(영어). 시프트만 짧게 탭(25~1500ms)하면 백스페이스.
  • 점4+5+6을 계속 누르고 있으면(약 0.5초) 영어↔한글 전환. 더 짧게 누르면 보통 점자 셀이다(한글 "것"의 약자 첫 셀과 같은 점형이라 시간으로 구분한다).
  • 이 숫자들(180, 25, 1500, 100, 500, 5ms)은 BrailleBridge의 값을 시작점으로 쓴 것이고, 실제 스위치와 실제 사용자로 맞춰 본 적이 없다.

영어와 한글의 차이

  • 영어: 한 번 친 글자가 곧 출력된다.
  • 한글: 한글 점자는 글자마다 초성·중성·종성이 셀로 나뉘고 약자가 있어서, 셀 하나만으로는 글자가 정해지지 않는다. 그래서 셀을 낱말 버퍼에 쌓고, 화면에는 지금까지의 해석을 보여 주다가, 스페이스(또는 언어 전환)에서 낱말을 확정해 한 번에 내보낸다. 백스페이스는 버퍼가 있으면 셀 하나 취소, 비어 있으면 이미 확정된 마지막 글자를 지운다.

화면

상태줄은 언어 BT 연결 c셀수 형식이다. 예: KO BT -- c04 = 한글 모드, 블루투스 미연결, 낱말에 셀 4개 쌓임. 본문은 커서(_)까지 포함해 최근 글자를 보여 준다. 한글은 두 칸, 영어는 한 칸을 쓴다.

  • T-Display: 30칸 × 7줄, OLED: 16칸 × 3줄.
  • 글꼴에는 KS X 1001 한글 2,350자만 있다. 나머지 8,822자는 화면에 ?로 나오지만 호스트로 보내는 글자는 정확하다.

4. 설계 결정과 이유

결정이유한계·대안
하드웨어는 고정, 언어는 소프트웨어 표선례가 영어+벵골어로 증명. 다른 나라 언어도 표만 넣으면 됨표마다 그 나라 점자 규정 확인이 필요
핵심 로직(판정·표·한글)을 하드웨어와 분리부품 없이 PC에서 자동 검증하려고실제 하드웨어 타이밍 문제는 여전히 실물에서만 보임
파이썬 기준 구현 → C++ 이식, 같은 테스트벡터 공유두 구현이 다르게 동작하면 바로 드러남벡터가 규칙을 빠뜨리면 둘 다 틀릴 수 있어서 벡터는 구현이 아닌 규칙에서 손으로 도출
블루투스 키보드는 검증된 라이브러리선례가 직접 구현으로 두 번 실패아두이노-ESP32 코어 3.x 호환은 아직 모름
한글은 낱말 단위로 다시 해석약자·초성/종성 구분이 앞뒤 셀에 좌우됨낱말이 끝나야 호스트로 나감
출력 두 갈래: 키보드 신호(HID)와 텍스트(시리얼)교사용 화면·앱은 유니코드 텍스트가 필요한글을 HID로 어떻게 보낼지는 미검증
화면은 한 코드로 두 보드사용자가 T-Display를 보유, 원래 계획은 OLED화면마다 크기·핀만 BrailleBoards.h에서 분기
소리 학습 모드는 후반핵심 기능(타이핑)이 먼저이어폰 전용으로 설계(시험 때 사생활 보호)

5. 맞는지 어떻게 알았나

"통과했다"가 아니라 "틀리면 실패하는 것을 확인했다"까지 가는 것이 이 프로젝트의 검증 원칙이었다.

  1. 테스트벡터 95개 — 글자 26개 × 소문자/대문자, 180ms 경계, 나중에 누른 점 무시, 시프트 탭 경계, 백스페이스 쿨다운, 언어 전환 500ms 경계 등. 기대값은 구현을 돌려서 얻지 않고 규칙에서 손으로 도출했다. 파이썬과 C++이 같은 파일을 읽고 같은 결과를 내야 한다.
  2. 변이 검사(mutation check) — 일부러 코드에 버그를 하나씩 넣고 테스트가 실패하는지 본다. 상수 ±1, 표 한 칸, 핀 번호 바꿔치기, 함수 호출 빼기 등을 넣어 봤다. 살아남은 버그는 테스트가 비어 있다는 뜻이라 그때마다 벡터를 추가했다(§6).
  3. 한글
    • 2024 개정 한국 점자 규정(문체부 고시, 시행 2024-03-01) 공식 문서에서 예시 291쌍을 추출했다. 한글·숫자·공백만으로 된 비교 가능한 예시 261개 중 255개를 인코더가 글자 그대로 재현하고, 재현하지 못하는 6개는 이유와 함께 목록에 남겼다(그 목록이 낡아 숨은 불일치를 가리지 않는지도 테스트한다).
    • 독립 출처(나무위키의 헌법 제10조 예문)의 점자를 낱말 단위로 디코드해 모든 낱말이 원문과 일치했고, 온점·반점 셀까지 확인했다.
    • 모든 한글 음절 11,172개를 인코드했다가 디코드해 돌아오는지 봤다. 규칙상 구별이 불가능한 11개 음절(예: 녜↔났처럼 같은 점형)만 다르게 읽힌다. 이 모호함은 문서에 적어 두었다.
    • 파이썬 디코더와 C++ 디코더를 101,611줄(모든 음절, 공식 예시, 무작위 낱말, 해석 불가 입력)로 대조해 모두 일치했다.
  4. 화면 — U8g2 글꼴로 화면을 PC에서 그려 PBM/PNG로 저장하고, 글꼴이 가진 모든 글자(ASCII + 한글 2,350자)가 줄 영역을 벗어나지 않는지, 글꼴에 없는 글자는 ?로 대신 그려져 뒤 글자가 밀리지 않는지 점검한다.
  5. 스케치 재생 — 스케치를 가짜 Arduino API로 PC에서 컴파일해 벡터를 핀 신호로 흘려 보낸다. 핀 번호가 명세와 같은지, 서로 겹치지 않는지, 그 보드에서 쓰면 안 되는 핀(화면·배터리·스트래핑)에 걸리지 않는지도 자동 확인한다.
  6. ESP32 컴파일 — 두 보드 모두 빌드된다(T-Display 445,895바이트 / OLED 386,432바이트, 앱 영역 1,310,720바이트).
  1. 시뮬레이터 — 펌웨어를 JS로 옮겨 브라우저에서 도는 가상 기기를 만들었다(firmware/simulator/simulator.html). 같은 규칙인지는 같은 방식으로 확인한다: 테스트벡터 95개, 파이썬 기준 구현이 정한 무작위 동시 입력 6,000개, 한글 101,611줄, C++가 그린 화면과 픽셀 단위 비교, 무작위 토큰 열에 대한 입력 계층 출력 비교. 엔진을 일부러 망가뜨려 테스트가 잡는지도 확인했다. 실제 스위치의 떨림·손가락 타이밍·화면 색과 크기는 다루지 못한다.

한 번에 돌리는 명령과 결과는 firmware/README.md에 있다.

7. 한글 점자에서 이 기기가 하는 일

  • 기준: 2024 개정 한국 점자 규정(2017 해설서는 구판이라 참고만).
  • 초성·중성·종성은 다른 점형이고, 된소리는 앞에 된소리표(⠠)가 붙는다.
  • 약자: 가·사·것, 나다마바자카타파하(초성만 쓰는 음절), 억언얼연열영옥온옹운울은을인(모음+받침 한 셀).
  • 약어: 그래서·그러나·그러면·그러므로·그런데·그리고·그리하여 (낱말 첫머리일 때만).
  • 그 밖에 붙임표(⠤), 수표(⠼)+숫자, 제14항(ㅏ 생략은 열린 음절 뒤 특정 조건), 제17항(ㅅㅈㅊ 뒤 영 약자) 등.

알려진 한계

  • 문장부호는 지원하지 않는다. 온점(⠲) 등은 받침 ㅍ 같은 다른 점형과 같아서 셀만으로는 구분할 수 없다.
  • 숫자 뒤의 한글에서 1년과 1 년은 점자로는 같아 구별할 수 없다.
  • ㅖ와 ㅏ+ㅆ가 같은 점형(34)이라 11개 음절은 규칙상 모호하다.
  • 이 표는 문서로 대조했을 뿐, 실제 점자 사용자·전문가에게 확인받지 못했다. 틀린 점자를 가르치는 도구는 해로우므로 공개 전에 반드시 필요한 단계로 남겨 뒀다.

9. 용어

  • 점자 셀: 점 6개(2×3)로 이루어진 글자 한 칸. 점 번호는 왼쪽 위→아래 1·2·3, 오른쪽 위→아래 4·5·6.
  • chord(동시 입력): 여러 키를 같이 눌러 한 글자를 만드는 입력 방식. 퍼킨스 브레일러가 이 방식이다.
  • 디바운스: 스위치는 눌리는 순간 접점이 떨려 신호가 여러 번 튄다. 이를 걸러 한 번의 눌림으로 만드는 것.
  • HID: 컴퓨터가 "키보드"로 인식하는 표준 방식. 블루투스 키보드는 이 방식으로 글자를 보낸다.
  • BLE: 저전력 블루투스.
  • PMM (Parametric Model Maker): MakerWorld에서 OpenSCAD 코드에 슬라이더 같은 입력창을 붙여 주는 기능.
  • OpenSCAD: 코드로 3D 모델을 만드는 도구.
  • 변이 검사: 코드에 일부러 버그를 넣어 테스트가 잡는지 확인하는 방법.
  • U8g2 / LovyanGFX: 화면에 글자를 그리는 / 화면을 구동하는 라이브러리.

점자 코드입력 키보드 — 만드는 설명서

LilyGO T-Display(판매 표기 TS0636G-T Display)로 점자 키보드를 만드는 순서다. 스위치 없이 지금 바로 할 수 있는 단계(0~3)부터 시작해서, 스위치를 달고, 영어와 한글을 쳐 보는 데까지 간다.

기준일: 2026-09-24. 전체 배경은 전체 과정 설명.

먼저 알아 둘 것 — 이 설명서는 아직 실물로 따라 해 본 적이 없다. 글쓴이(Claude)는 하드웨어에 손이 닿지 않는다. 그래서 모든 단계에 아래 표시를 붙였다.

  • PC 검증됨: 자동 테스트로 확인한 동작. 예상 출력은 믿어도 된다.
  • 실물 미검증: 실제 보드·스위치·화면이 있어야 알 수 있다. 틀릴 수 있으니 안 맞으면 그대로 알려 달라. 알려 주면 코드와 이 문서를 고친다. 맨 끝의 실물 검증 기록표를 채우면 된다.

부품이 오기 전에 — 시뮬레이터로 손에 익히기

점자 chord 입력(여러 키를 동시에 눌러 한 글자)은 손에 익어야 편하다. 저장소의 firmware/simulator/simulator.html을 브라우저로 열면 가상 기기가 펌웨어와 같은 규칙으로 동작한다. 키보드 A S D F Space J K L이 시프트·점3·점2·점1·스페이스·점4·점5·점6이고, 영어와 한글 낱말을 연습하면 다음에 누를 키를 알려 준다. 이것은 PC 시뮬레이션이라 실제 스위치의 감각, 화면의 실제 모습, 블루투스는 다르다.

1단계 — 소프트웨어 준비

방법 A: arduino-cli (이 PC에서 빌드까지 확인한 방법)

이 PC에는 이미 설치돼 있다 — arduino-cli 1.5.1, ESP32 코어 3.3.12, 라이브러리 U8g2·LovyanGFX. 다른 PC라면:

arduino-cli config add board_manager.additional_urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core update-index
arduino-cli core install esp32:esp32@3.3.12
arduino-cli lib install U8g2 LovyanGFX

저장소 맨 위 폴더(openscad-makerlab)에서 빌드한다. 컴파일 성공 (445,895바이트, 앱 영역의 34%)

arduino-cli compile --fqbn esp32:esp32:esp32 --libraries firmware/libraries --build-path firmware/build/sketch_tdisplay firmware/braille_keyboard

방법 B: Arduino IDE 2.x

이 PC에서 IDE로는 시험하지 않았다(arduino-cli로만 빌드 확인).

  1. 환경설정의 "추가 보드 관리자 URL"에 위 package_esp32_index.json 주소를 넣고, 보드 매니저에서 esp32 (Espressif Systems) 3.3.12를 설치한다.
  2. 라이브러리 매니저에서 U8g2와 LovyanGFX를 설치한다.
  3. firmware/libraries/BrailleCore 폴더째 문서\Arduino\libraries\ 안으로 복사한다.
  4. firmware/braille_keyboard/braille_keyboard.ino를 열고 보드를 ESP32 Dev Module로 고른다.

보드 고르기

스케치 맨 위에 #define BRAILLE_BOARD_TDISPLAY가 기본으로 켜져 있다(T-Display). ESP32 DevKit + SSD1306 OLED를 쓰면 빌드 옵션 -DBRAILLE_BOARD_DEVKIT_OLED를 준다(firmware/README.md).

2단계 — 화면부터 켜 보기 (스위치 없이)

실물 미검증 — 이 단계가 가장 먼저 실물로 확인할 것이다. 화면이 안 나오면 이 뒤는 의미가 없다.

  1. T-Display를 USB-C로 PC에 꽂는다.
  2. 포트를 찾는다.
    arduino-cli board list

    COM3 같은 포트가 보여야 한다. 안 보이면 케이블이 충전 전용이거나, USB-시리얼 칩(CH9102) 드라이버가 필요할 수 있다(제조사 안내 참고).

  3. 업로드한다 (COM3는 본인 포트로).
    arduino-cli upload -p COM3 --fqbn esp32:esp32:esp32 --input-dir firmware/build/sketch_tdisplay firmware/braille_keyboard

    Connecting...에서 멈추면 일반적인 ESP32 방법으로 GPIO0 버튼을 누른 채 다시 시도한다.

  4. 시리얼 모니터를 열고, 보드의 리셋(RST) 버튼을 누르거나 USB를 다시 꽂는다.
    arduino-cli monitor -p COM3 -c baudrate=115200

기대하는 모습 (PC에서 같은 코드로 그린 화면이다 — 실제 색과 크기는 다를 수 있다)

3단계 — 스위치 없이 신호 시험

실물 미검증, 동작 자체는 PC 검증됨

전선 한 가닥으로 GPIO 핀 ↔ GND를 잠깐 이으면 스위치를 누른 것과 같다(스위치 한쪽은 GPIO, 다른 쪽은 GND에 연결할 것이므로). 핀은 내부 풀업이라 아무것도 안 이으면 "안 눌림"이다.

주의: GPIO를 GND에만 잇는다. 3V3·5V에 잇지 않는다. 화면이 쓰는 핀(18·19·5·16·23·4)도 건드리지 않는다.

  1. 점1(GPIO13) ↔ GND를 잠깐 이었다 뗀다.
    • 시리얼: OUT,<시각>,a 다음에 HOST,<시각>,TEXT,a
    • 화면: a_
  2. 스페이스(GPIO32) ↔ GND: OUT,…,SPACE, HOST,…,TEXT,
  3. 시프트(GPIO21) ↔ GND를 짧게(0.03~1.5초) 이었다 뗀다: OUT,…,BKSP, HOST,…,BKSP, 화면에서 마지막으로 친 것(여기서는 공백)이 지워진다.

글자는 점 키를 모두 뗄 때, 또는 처음 누른 뒤 0.18초가 지나면 나온다. 시리얼 줄 앞의 숫자는 보드가 켜진 뒤 밀리초다.

화면은 손가락(전선)을 모두 뗀 뒤 잠깐 있다가 갱신된다. 키 입력을 방해하지 않으려고 일부러 그렇게 했다. 그래서 눌러 둔 동안에는 화면이 바뀌지 않는다.

실물 미검증

6단계 — 한글 쓰기

변환(점자 → 한글)은 PC 검증됨 / 실기 입력과 호스트로 보내기는 미검증

  1. 언어 전환: 점4·점5·점6을 같이 누르고 그대로 약 0.5초 잡고 있는다. 손을 떼면 화면 맨 윗줄이 KO로 바뀐다(화면은 손을 뗀 뒤에 갱신된다). 같은 동작으로 EN으로 돌아온다. (0.5초보다 짧게 누르면 그냥 점자 셀 하나가 입력된다.)
  2. 한글 모드에서는 친 점자 셀이 낱말 버퍼에 쌓인다. 화면에는 지금까지 해석한 낱말이 커서와 함께 보이고, 상태줄 c04는 쌓인 셀 수다.
  3. 스페이스를 누르면 낱말이 확정되어 호스트로 나가고(지금은 시리얼의 HOST,…,TEXT,한글), 버퍼가 비워진다.
  4. 백스페이스(시프트 탭): 쌓인 셀이 있으면 셀 하나만 취소, 없으면 이미 확정된 마지막 글자를 지운다.

8단계 — 블루투스

아직 만들지 않았다. 지금은 글자가 시리얼로만 나간다(HOST,… 줄). 다음 작업은 이렇다.

  • 검증된 BLE 키보드 라이브러리를 골라, 아두이노-ESP32 코어 3.x와 맞는지 확인한다.
  • 영어는 키 코드를 그대로 보내면 된다.
  • 한글은 방식 자체가 미검증이다. 지금 구상은 한글 자모를 (두벌식) 키 코드로 보내 폰·PC의 한글 입력기가 조합하게 하는 것인데, 실제로 기기에서 시험해 봐야 안다.
  • 폰·PC에 페어링해 글자가 들어오는지, 화면읽기 프로그램이 읽어 주는지 확인한다.

문제 해결

증상가능한 원인해볼 것
키를 눌러도 시리얼에 OUT이 안 나온다배선, 핀 번호3단계처럼 GPIO↔GND를 전선으로 직접 이어 본다. 되면 스위치 쪽 접촉 문제
눌렀는데 엉뚱한 글자가 나온다핀이 뒤바뀜4단계 표와 배선을 대조. 시리얼의 CELL:이나 글자로 어떤 점이 눌렸는지 본다
한 글자를 쳤는데 두 글자로 갈라진다점들을 0.18초 안에 못 누름동시에 누르는 연습. 계속 그러면 알려 달라(창 길이를 조정할 수 있다)
같은 글자가 두 번 나온다스위치가 튐, 접촉 불량시리얼에서 시각을 본다. 디바운스 시간을 조정할 수 있다
언어가 안 바뀐다세 점을 같이 못 눌렀거나 너무 빨리 뗌점4·5·6을 같이 누르고 0.5초 이상 유지
한글 모드인데 낱말이 ?로 보인다해석할 수 없는 셀 열, 또는 화면 글꼴에 없는 글자백스페이스로 셀을 지워 보며 어디서 ?가 생기는지 본다. 시리얼의 HOST 줄은 정확한지 확인
업로드 실패충전 전용 케이블, 드라이버, 포트데이터 케이블로 바꾸고 board list로 포트를 확인. 그래도 안 되면 GPIO0 버튼을 누른 채 시도
